## Challenges

- **Epic was lightweight** — 2/3 stories test-only, no complex Effect patterns exercised. Team not stress-tested before critical Epics 6–8.
- **Subtle Ref/Effect timing in tests** (Story 5.2): polling `getProgress()` inside `uploadPart` for part 1 sees 0 bytes because `Ref.update` fires after `uploadPart` resolves. Required adjusting poll to part 2. Pattern to document.

## Key Insights

1. **Anticipative architecture pays off**: Extension points planned early (`LoggerService` in Epic 1, `getProgress` in Epic 3) reduced Epic 5 to mostly validation work. Continue this pattern.
2. **Opus for dev eliminates a variable**: Consistent agent quality across dev + review removes uncertainty on critical epics. Decision made to standardize.
3. **The improvement cycle works**: Task 0 pattern, `project-context.md`, triptyque enforcement — all proven effective across multiple epics. Trust the process.
4. **Project inflection point**: 5/9 epics delivered. Epics 6–8 (resilience, resumability, adapters) are where the library's real value materializes. Foundations are solid.
