### Library Bugs Discovered AND Patched During Epic 10

1. **`s3MultipartUpload` parts sort** — completed parts must be ordered by `partNumber` before `CompleteMultipartUpload`; otherwise S3 returns `InvalidPart`. Patched in v0.1.2.
2. **`safeLog` logger-resilience** — user-injected throwing Logger crashed the upload fiber via `Effect.sync(() => logger.log(...))`. Replaced all internal log call sites with `safeLog(logger, level, message, data?)` (`Effect.ignore(Effect.try(...))`). Locked in by 10.1-INT-013 (F#66).
3. **README peer-dep accuracy** — original wording over-claimed the `effect` peer-dep contract; Context lookup is KEY-based not identity-based. README updated; peer-dep contract still load-bearing for `instanceof`, version skew, bundle bloat — *not* for Layer lookup failures.
4. **README `Match.tag` syntax** — example contained an unreachable variant; the 9-variant `UploadError` union requires exhaustive handling. Fixed in v0.1.2 README + locked in by 10.6-D-003.

## Challenges

1. **Test-app harness fragility was the dominant pain point.** Seven separate MEMORY entries document bugs paid in debug time: zombie Vite servers, `tsx watch` stale in-memory state, fetch monkey-patches filtering on port instead of path, `purgeUploads()` per-test racing with parallel browser workers, chaos endpoint singleton not being session-scoped initially, resume-test bypass needed because `appPage` `addInitScript(localStorage.clear)` wiped ResumeState, log batches not flushing until upload completes. Each one is a real bug paid in debug time.
2. **Symptom signature is always "this fix should work but doesn't".** The harness bugs are silent — a test goes red and the first instinct is to dig in the lib. The reactive countermeasure ("probe with `curl` first") emerged ad hoc and isn't yet captured as a runbook.
3. **Sprint-status tracking lapsed.** Epic 10 has no `10-*.md` story files in `implementation-artifacts/` and no Epic 10 rows in `sprint-status.yaml`. The tracking discipline of Epics 1–9 was set aside mid-epic; this retro recovers it.
4. **Vitest dynamic-import limitation surprised the doctest harness work.** Vite's `loadAndTransform` refuses paths outside the project root; `new Function("return import(...)")` also failed. Workaround: spawn a fresh Node child process via `spawnSync`. Documented but cost time on Story 10.6.
5. **Effect-pattern subtleties keep surfacing.** TestClock requirement for `Schedule.exponential`, `normalizeCallback` double-wrapping with Effect-typed callbacks, `Ref.update` post-`uploadPart` timing, `.finally()` re-propagating on rejected Promises — each one a half-day surprise that landed in MEMORY.

## Key Insights

1. **Test-coverage epics pay on the library, not just on the tests.** Four real bugs surfaced — this is the strongest possible argument that Epic 11 / 12 / 13 carry their own ROI. To carry forward into Epic 11.
2. **Surgical-test discipline holds at scale.** Even with 8 stories and ~25 net-new tests planned, the actual net-new count was 4, with the rest being annotations or genuinely-needed integration coverage. The `feedback_surgical_tests.md` rule is confirmed under load.
3. **Test-app harness is the dominant cost center going forward.** Pain Epic 10 and worry Epic 11 converge on the same object. Action items #2 + #3 below address it from both sides (root cause + structural shift).
4. **Sprint-status discipline only holds with hard structure.** When story files in `implementation-artifacts/` get skipped, sprint-status.yaml silently drifts. Re-establishing for Epic 11.
5. **MEMORY.md is being used heavily and correctly.** Epic 10 produced ~20 distinct pattern memories — each one a documented gotcha future-Claude can read. The system works as designed; the *cost* is captured even when the *time* spent isn't.
