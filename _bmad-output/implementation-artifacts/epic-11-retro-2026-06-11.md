## Successes

- **The library is maturing.** Only **1 lib fix** across 89 P2 scenarios (vs 4 in Epic 10). 6/7 stories were pure surface-area locks — the behaviour was already correct. The epic's value shifted to *regression-locking + surfacing a concrete Epic 13 backlog*.
- **The Codex-substitute review loop works.** Dev-in-context → fresh-context Opus `code-reviewer` earned its keep: caught a real tautology + a CORS false-positive in 11.7; confirmed clean with *traced* non-tautology proofs in 11.3 / 11.5 / 11.4. Always re-verified green locally, never trusting the reviewer's claims blind.
- **D3 WebKit commitment paid off.** 11.4 personas green on all 3 engines first try — zero `@flaky` demotions, no pre-emptive skips. CDP gated to Chromium with a portable slowSign stand-in elsewhere.
- **Honest-scope discipline held.** No tautologies shipped: 11.7 D-001 reworked into a real two-session crash-resume; 11.4 C2 locks *actual* current behaviour (`ReconcileError`, object absent — verified by live MinIO probe) rather than the idealized AC text.
- **Reusable harness assets compounded** — 11.5 chaos harness (`context.route` PUT-level injection), 11.4 persona helpers (portable `page.route` offline, session-tagged chaos), doctest harness. Each story got cheaper.
- **Surgical-test discipline** — exact `_tag` assertions, exact counts (B6's "exactly 6 sign calls"), defect-refusal patterns (`Cause.dieOption`).

## Challenges

- **Test-app harness remains the dominant cost centre** (Epic 10's prediction, confirmed). 11.4 needed 3 new query-param debug toggles; the A2 CPU-throttle-before-`setInputFiles` timing bug cost a debug cycle. If PW-UI coverage grows, a structural investment (typed debug-config endpoint?) would pay back.
- **AC text drifted from the real API.** AC#5 wrote `Schedule.recurs(10).pipe(Schedule.fixed("1 second"))` — literally invalid Effect (`fixed` is not a pipe combinator). AC#6 said "reconcile returns empty" — factually wrong vs MinIO (`ListParts` on an aborted uploadId *throws* `NoSuchUpload`). Both forced dev-time interpretation. The ACs came from a brainstorming session and were never validated against the real surface.
- **A real lib limitation surfaced (11.5):** the events `ReadableStream` reads **empty** on the failure/abort path — it errors without flushing buffered `UploadEvent`s. Worked around throughout with callback-side counters; now an Epic 13 candidate.
- **The test-app is outside the typecheck gate.** A pre-existing latent `@types/node` error (`body: chunk` — `Uint8Array` vs `BodyInit`) is invisible to `turbo typecheck` because the test-app has no `typecheck` script. Untouched (out of scope), but worth a future one-liner cast + gate.

## Key Insights

1. **Diminishing library-bug yield is itself the signal.** 1 fix / 89 scenarios means the P2 risk surface is mostly discharged. Future test epics should explicitly budget for "expected lib fixes ≈ low" and value regression-locking + candidate-surfacing as the primary ROI.
2. **A concrete, test-backed Epic 13 backlog is the main forward artifact.** ~14 candidates, each with a *locking test already in place* that documents the desired behaviour — so Epic 13 stories are unusually shovel-ready ("flip the lock").
3. **Brainstorming-sourced ACs need an API-validation pass.** Two of 11.4's seven ACs were unrunnable as literally written. A cheap "compile the AC snippets / probe the real service" step during story creation would catch this before dev.
4. **The dev-in-context + fresh-Opus-reviewer loop is a durable Codex substitute** — but only because every "green" and every finding was independently re-run by the parent.
