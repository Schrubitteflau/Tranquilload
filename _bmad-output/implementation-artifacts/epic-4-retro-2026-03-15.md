## Challenges

- **`any` type parameters in public interfaces**: `MultipartPublicOptions.pipeline` and `OneShotPublicOptions.pipeline` typed as `Transform | Effect.Effect<Transform, any, any>`, propagating `any` into internal casts (`as Effect.Effect<Transform, any, never>`). Sacrifices type-safety for convenience.
- **`algorithm: string` too permissive**: `CompressionService.compress()` and `compress()` accept `string` then cast to `CompressionFormat` — accepts invalid algorithms silently at the type level.
- **Pre-existing TS errors carried forward**: 11 TypeScript errors in `oneshot/upload.test.ts` and `oneshot/index.test.ts` (possibly-undefined access + `totalParts` property not yet on `UploadEvent`). Noted in Stories 4.2 and 4.3 with "do not fix" — accumulated across 2+ stories.
- **`pnpm turbo typecheck` not part of mandatory validation**: Stories validated with build + test but typecheck was secondary, allowing TS errors to persist unaddressed.

## Key Insights

1. **`any` in public interfaces cascades into internal casts**: Fixing the public type (`unknown, unknown`) eliminates the need for internal `as Effect<..., any, never>` casts. Fix at the source.
2. **Typecheck must be mandatory, not advisory**: Without enforcement, type-level debt accumulates silently. The triptyque build + test + typecheck is the correct baseline.
3. **The improvement cycle continues to work**: Task 0 pattern for retro action items, `project-context.md` for recurring patterns — both proven effective across multiple epics.
