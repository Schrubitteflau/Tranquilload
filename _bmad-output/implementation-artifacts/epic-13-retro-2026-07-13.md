## Epic Summary

Epic 13 took the **test-backed candidate backlog** surfaced by the Epic 11 retro (~14 candidates, each with a locking test already in place) and turned the deliverable ones into **opt-in, non-breaking library hardening**. The defining mechanic: every story either **flipped an existing locking test in place** (gap → validated fix) or, when the named lock was the wrong tier/shape, **locked net-new at the right tier and re-tagged** the named lock. The defining constraint: every new option is **opt-in, default byte-for-byte unchanged → non-breaking → pre-1.0 patch**.

The epic's signature process was the **API-validation / design pass run *during story creation*** — the Epic 11 retro's #3 recommendation, promoted to load-bearing. It paid off most visibly by **declining two whole stories** (13.5b, 13.7) rather than shipping a dishonest lock for an AC the platform can't honestly deliver.

## Successes

- **Zero High / zero Medium review findings across the entire epic.** Six independent fresh-context Opus reviews produced only 19 Low nits (a handful applied, most declined as informational). The flip-the-lock discipline + surgical tests + "dev-in-context, parent re-verifies green" loop produced consistently clean code.
- **The API-validation/design pass earned its keep by saying NO.** Its highest-value output wasn't a feature — it was **declining two stories** (13.5b, 13.7) rather than shipping a dishonest lock, plus re-scoping several others. "Grep whether the capability already exists before adding a knob" (heuristic ii) killed both: `uploadPart(_, chunk)` already hands the caller the exact bytes to checksum (13.5b), and `CompleteUploadError` → re-probe → re-invoke with a fresh source already recovers a GC'd part (13.7).
- **Non-breaking discipline held perfectly.** Every shipped feature is opt-in with the default path byte-for-byte unchanged; every changeset was pre-1.0 patch. No accidental default change, no surprise 1.0.0 leapfrog across 5 releases.
- **Tier-correct locking generalized cleanly.** Three times the named lock was the wrong tier — an E2E/MinIO chaos spec standing in for a deterministic *unit* behaviour (a runtime callback/`Duration`/decision can't cross `page.evaluate`). Each time: lock net-new at the unit tier + re-tag the E2E (13.4 `11.5-E2E-010`, 13.5 `11.2-INT-005`, 13.6 `11.7-E2E-002`). The E2E stays a true negative lock of the platform fact.
- **The protocol-agnostic core stayed protocol-agnostic.** Every new classification is **caller-supplied and phase-guarded** — `reinitOnStale`, `failFast`, `abortUpload` all predicate on the *raw cause* or the upload *phase*, never on S3 error strings. The core never learned to parse a transport's wire format.
- **Cause-only errors stayed out of the discriminated union.** `PartTimeoutError` (13.4) feeds `retrySchedule` via `PartUploadError` but is not a `UploadError` variant — the union stays phase-accurate.

## Challenges

- **The Epic 11 candidate backlog over-counted deliverables.** 2 of the 14 candidates (F#70 "a checksum catches a buggy compressor"; F#14 "detect & re-upload a GC'd reconciled part in-band") promised something no honest generic API can deliver — a digest of the uploaded bytes matches the corrupt output; a memory-safe single-pass re-upload of an arbitrary GC'd part needs unbounded retention that defeats resume. Not a failure (the design pass caught both), but future backlog-harvesting should tag candidates **"design-pass-required" vs "shovel-ready"** up front.
- **Release cadence was choppy — 5 cycles for 8 stories.** 0.1.3 bundled 13.1/13.2/13.4; 13.3 got a solo 0.1.4; 13.5+13.5b shared 0.1.5; 13.6 shipped adapters 0.1.6; 13.7 is a solo pending 0.1.7. More bundling would have cut release overhead. (This retro applies the lesson: 13.7's docs ride a single 0.1.7.)
- **Linked-group version math bit twice.** core+adapters are a changesets `linked` pair, so a bump jumps to `max(group) + bump`, not the package's own `+1`: 0.1.4 was skipped for core, and adapters' "0.1.4" patch actually published as **0.1.6** (group max core 0.1.5 + patch). Now documented in MEMORY, but a recurring foot-gun — **predict from the group max.**
- **test-app still outside the typecheck gate** (Epic 11 carry-over, unresolved). The latent `body: chunk` `@types/node` error is still invisible to `turbo typecheck`.
- **MEMORY.md is over its size budget** (24.9KB > 24.4KB warn) — index entries grew too long across the epic. A housekeeping trim is pending.

## Key Insights & Reusable Playbook (the main forward artifact)

This is the harvest — the heuristics proven across 13.1→13.7, reusable for any reopened Epic 13 work **and for Epic 12**.

### Flip-the-lock mechanic
1. **Behaviour-CHANGING story:** EDIT the existing locking test in place — strip the `// Epic 13 candidate` comment, INVERT or add the opt-in arm, **KEEP the `F#N`/test-ID prefix, do NOT duplicate.**
2. **When the named lock is the wrong TIER or SHAPE:** lock NET-NEW at the right tier + **RE-TAG** (not flip) the named lock. Proven 3× (13.4/13.5/13.6). An E2E/MinIO spec is the wrong place to flip a deterministic unit behaviour — a runtime callback/`Duration`/decision can't cross `page.evaluate`.
3. **When the AC is undeliverable:** the lock stays GREEN and is NOT flipped; the story resolves decline/document-only (13.5b `11.2-INT-005`/F#70, 13.7 `11.3-INT-005`/F#14).

### API-validation / design pass — run it DURING story creation, before dev
- **(i) Check the named lock's TIER.** Unit behaviour ⇒ unit lock; re-tag any E2E that only witnesses the platform fact.
- **(ii) Grep whether the capability ALREADY EXISTS before adding a knob.** Ship as sugar or decline. This alone declined 13.5b *and* 13.7 — the recovery/checksum was already caller-achievable.
- **(iii) Cause-only errors stay OUT of the discriminated union** (`PartTimeoutError` is a cause, not a `UploadError` variant).
- **(iv) Keep classification caller-supplied / phase-guarded** so the core stays protocol-agnostic — predicate on the raw cause, never inspect a transport's error strings.
- **(v) When a brainstorming AC promises what the platform can't honestly deliver, surface the fork via `AskUserQuestion` + decline/reframe** rather than ship a dishonest lock. Two stories resolved this way, both on honesty/cost — never feasibility.
- **Spike-gated stories need the design pass + AskUserQuestion fork-surfacing BEFORE dev.** Do not pick one as a quick-win. (13.3/13.5/13.6 were spike-gated; 13.5b/13.7 declined via the pass.)

### Non-breaking & release discipline
- **Every new option opt-in; default preserves current behaviour** → non-breaking → **pre-1.0 patch** changeset (don't forget it). Adapter-only ⇒ changeset targets `@tranquilload/adapters`; core ⇒ `@tranquilload/core`. They publish together as a `linked` pair regardless.
- **Linked-group version math:** predict the next version from **`max(group) + bump`**, not the package's own current version.
- **Releases are CI-native:** don't `changeset version` locally — push master, let `changesets/action` maintain the "Version Packages" PR, gate on a **green local lib-smoke** (the bot PR shows no checks / UNSTABLE — benign), then squash-merge to publish. **Confirm before merging — publish is irreversible.**
- **Prefer bundling** doc-only / small changesets into one release cycle (this epic ran 5 cycles for 8 stories; fewer would have been cleaner).

### Review loop (Codex unavailable)
- Dev-in-context → **fresh-context Opus `code-reviewer`** (`subagent_type: code-reviewer`, `model: opus`). Apply `receiving-code-review` skepticism in both directions and **always re-run the tests yourself** to verify findings AND "green" claims. A doc-only story may skip the formal review — PL's call (13.5b, 13.7 did).
