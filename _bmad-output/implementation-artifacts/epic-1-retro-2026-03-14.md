## Successes

- **Story spec quality drives code quality**: Detailed story specs with code examples and explicit constraints enabled Sonnet to produce conformant code on first pass. Story 1.4 achieved a clean review with zero findings.
- **Consistent velocity improvement**: Story 1.1 had significant tooling friction; by Story 1.4, dev-to-review was smooth.
- **Zero technical debt**: Foundation epic delivered clean — no shortcuts, no deferred work.
- **Lessons documented and retained**: Tooling discoveries (Node 22, vitest 3.x, pnpm naming) captured in MEMORY.md and story Dev Notes — no regressions in subsequent stories.
- **Sonnet (dev) + Opus (review) cycle works**: Clear role separation — Sonnet produces functional code, Opus catches assertion gaps and edge cases.

## Challenges

- **Test assertions too permissive in early stories**: Stories 1.1–1.3 reviews consistently found tests that checked for failure presence (`Exit.isFailure`) without validating the specific error type and content. Improved progressively through reviews.
- **Tooling friction concentrated in Story 1.1**: Node.js 20 incompatible with tsdown/rolldown, vitest 3.x exit code 1 with no test files, pnpm scoped package directory naming conflict, invalid npm package name `@tranquilload`. All resolved and documented.
- **Architecture doc partially invalidated**: `isolatedDeclarations: true` specified in architecture doc is incompatible with Effect's `Context.Tag` class pattern (TS9021). Discovered during Story 1.3 implementation. `project-context.md` still references the outdated constraint.

## Key Insights

1. **Story spec quality is the #1 lever** for code quality — invest there.
2. **Surgical tests > test volume**: 5 tests that prove the exact contract are worth more than 20 with soft assertions. Every failure test must extract the `Cause` and validate error type + content.
3. **Sonnet + Opus cycle confirmed**: Sonnet for dev speed, Opus for review depth. Each catches what the other misses.
4. **Tooling discoveries don't repeat** when properly documented in MEMORY.md.
